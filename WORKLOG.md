# PikoVK — Worklog

Лёгкий Android WebView-браузер для VK (Kotlin, `com.pikovk.browser`).
Формат: свежие записи сверху. Детали реализации — в README.md.

## 1.3.23 (versionCode 28) — вкладка-плеер «Музыка» (VK Music Player), старые кнопки скачивания убраны

- Симптом владельца: «скачивание аудио нормально не работает ни в мобильной, ни в полной версии; значок скачивания накладывается на элементы трека; сделай отдельной вкладкой, чтобы был весь функционал VK Music Player».
- **УБРАНО полностью**: JS-секция `AUDIO_DL_JS` (кнопки «↓» в страницах VK — источник наложения на элементы), тумблер «Кнопки скачивания у треков», `AudioGrabber`, `VkbBridge.downloadAudioTrack`. Страницы VK больше не трогаются вовсе.
- **НОВАЯ вкладка «Музыка»** (кнопка-нота на нижней панели, `music/MusicActivity` + `assets/music.html`, тёмная тема): собственный плеер ВНЕ страниц VK, по образцу VK Music Player от VK Next. Функционал: «Моя музыка» (audio.get, пачки по 50, бесконечный скролл), поиск (audio.search, дебаунс 400 мс), плейлисты (audio.getPlaylists → audio.get по album_id) с входом/выходом, обложки (album.thumb.photo_300), значки битрейта (~Nk, как в расширении), серые строки для ограниченных/DMCA треков. Плеер: play/pause/next/prev, seek, шаффл (Фишер–Йетс с выводом текущего трека вперёд), повтор (выкл/все/один), тайминги, обложка в нижней панели. Скачивание: у каждого трека кнопка «⤓» В НАШЕМ UI (страницы VK не затрагиваются) — mp3 в «Загрузки» через DownloadManager, HLS — сегменты в один .ts в «Загрузки» (MediaStore на Android 10+, файл на 8–9; конвертации в mp3 нет — её у VK Next делают ffmpeg.wasm/сервер; .ts играют VLC/MX Player).
- **Механизм 1:1 из VK Music Player** (CRX распакован, ключевые фрагменты сверены вручную + тест эквивалентности на 303 случая): web-токен `POST login.vk.ru/?act=web_token` (version=1&app_id=6287487, cookie веб-сессии, Origin vk.ru) → API `POST api.vk.ru/method/*?client_id=6287487` (v=5.251, lang=ru, retry 6/9/10), ссылка трека: `audio_streams[type=hls_ts].url` иначе `url`, маскированные ссылки разворачивает дословный порт `audioUnmaskSource` (алфавит сверён с бандлом), битрейт: mp3 — Content-Length*8/длительность, HLS — один сегмент (байты*8*(total/сегм)/1000), кэш по rawId.
- **HLS в WebView**: hls.js 1.5.20 (light, BSD) в assets; CORS для XHR-сегментов открывает `shouldInterceptRequest` — `Access-Control-Allow-Origin:*` ТОЛЬКО к ответам аудио-CDN (vkuser.net/vkuseraudio.ru/userapi.com/okcdn.ru/...) — эквивалент DNR-правила 8 расширения; остальное насквозь.
- Медиашторка/гарнитура работают без изменений: `music.html` реализует тот же протокол `window.__vkbPlayerCmd` и репортит метаданные через `VkbMusic.playerState` (та же логика упреждающего запуска FGS, 1.3.22). `PlaybackService` не менялся.
- Поведение: поворот экрана плеер не пересоздаёт (configChanges); wake-lock/служба управляются MainActivity (вкладка всегда поверх неё); ЗАКРЫТИЕ вкладки останавливает музыку (WebView живёт в активности; непрерывное фоновое воспроизведение после закрытия — кандидат на отдельную версию: свой плеер в службе).
- Контроль: `scripts/check_piko_1323.py`, `scripts/test_unmask_port.py`. Новый код: `music/MusicApi.kt`, `music/MusicBridge.kt`, `music/MusicActivity.kt`, `assets/music.html`, `assets/hls.min.js`, `res/layout/activity_music.xml`, `res/drawable/ic_music.xml`.
- Фикс компиляции (сборка владельца): в `MusicActivity` забыли `import androidx.activity.addCallback` — без него лямбда `addCallback(this) {}` не резолвится (в `MainActivity` импорт был, там поэтому собиралось); в `MusicApi.unmask` smart cast по `var vals`, переприсваиваемой в цикле, компилятор не держит — null гасится явно (`val decoded` + отдельная проверка), дальше `vals` живёт как заведомо не-NULL `String`. Там же убран избыточный инициализатор `var kbps` в `probeBitrate` (обе ветки if/else присваивают до чтения — w: initializer is redundant).
- Фикс первого запуска (жалоба: «не вижу полного запуска плеера и стрелочек скачивания»): в `myMusic`/`playlists` выход при `uid==0` стоял ЕЩЁ ДО `token()` — а uid проставляется только токеном, поэтому «Моя музыка» и «Плейлисты» на первом запуске падали навсегда (треков нет → плеер не стартует → стрелки ⤓ не рисуются — они на строках треков ВНУТРИ вкладки, в страницах VK их больше нет с 1.3.23). Теперь при uid==0 сначала добывается токен. Плюс UA всех музыкальных запросов теперь = UA WebView браузера (`Prefs.desktopMode ? DESKTOP_UA : effectiveMobileUa`) — web-сессия VK выдана этому UA, Dalvik-UA мог отклоняться на web_token. Поиск работал и раньше (проверки uid там не было) — потому баг выглядел «не всегда».
- Фикс фона вкладки «Музыка» (жалоба: «при блокировке экрана или сворачивании перестаёт играть и скидывается»): (1) `MainActivity.onStart` БЕЗУСЛОВНО глушил `PlaybackService` — а медиа-карточка (шторка/локскрин) своим contentIntent поднимает MainActivity НАД играющей вкладкой: процесс падал в кэш, замораживался (Android 12+), музыка обрывалась, вкладка сбрасывалась. Теперь на `onStart` служба глушится только когда ничего не играет (`PlaybackService.isPlaying()`). (2) Служба держит СВОЙ частичный wake-lock (`PikoVK:playbackSvc`) ровно пока живёт — CPU больше не зависит от жизненного цикла активити (раньше lock держал только `MainActivity.onStop`, а вкладка живёт поверх MainActivity). (3) Рендереру вкладки запрещено «списывание» в невидимости — `setRendererPriorityPolicy(IMPORTANT, false)` (раньше true, как в браузере). (4) Тап по медиа-карточке теперь открывает саму вкладку «Музыка» (`attachMusicTab`/`fromMusicTab`), а не браузер поверх плеера — раньше это выглядело как полный сброс.
- Фикс фона №2 — ПОЛНЫЙ АУДИТ МЕХАНИЗМОВ ВЫЖИВАНИЯ (жалоба повторилась после первого фикса: «не в фоне ни при блокировке экрана музыка не продолжает работать, хотя уведомления включены»). Пересчитаны все механизмы Android 12-16: кэш-фризер (лечится FGS), фантомный киллер рендереров (лечится FGS + обработчик смерти рендерера), требования FGS mediaPlayback 14-16 (тип в манифесте + разрешения + старт из видимого состояния — всё было), Doze (FGS даёт сеть без ограничений), OEM-убийцы (вне кода). Найдены и закрыты 3 пробоины + 2 страховки:
  1. **`MainActivity.onDestroy` безусловно глушил `PlaybackService`** — главный убийца. Вкладка «Музыка» лежит ПОД MainActivity, систему ничего не обязывает хранить остановленную активити: при блокировке/сворачивании память или прошивка УНИЧТОЖАЮТ MainActivity → onDestroy → `PlaybackService.stop()` → процесс в кэш → заморозка за ~10 с → фантомный киллер добивает рендерер: звук обрывается, вкладка сбрасывается. Теперь служба/lock/ссылка гасятся только если звук НЕ вкладки «Музыки» (`fromMusicTab && isPlaying`).
  2. **В `MusicWebClient` не было `onRenderProcessGone`** — смерть рендерера без обработчика валит ВЕСЬ процесс приложения (документированное поведение WebView). В браузере обработчик был (`VkWebViewClient:360`), во вкладке забыли. Добавлен: `return true` + тихая пересборка вкладки (сборка WebView вынесена в `buildPlayerWebView`, как `buildWebView` в MainActivity), репорт «не играет» в шторку, лог `PikoVK-Music`. Очередь плеера восстанавливаться не может (живёт в JS страницы) — но приложение больше не «скидывается».
  3. **«Кража» ссылки шторки**: `MainActivity.onStart` и `buildWebView` прикрепляли браузерный WebView безусловно — пересоздание MainActivity поверх играющей вкладки уводило команды шторки в браузер и сбрасывало `fromMusicTab`. Оба места защищены проверкой `!PlaybackService.fromMusicTab`.
  4. **Страховка `MusicActivity.onStop`**: если играет, а службы нет (MainActivity уже уничтожена — упреждение моста и добор из её onStop не сработали), вкладка сама поднимает FGS + wake-lock в момент ухода с экрана (внутри grace-окна «переход из видимого состояния»).
  5. **Страховка от тихой демотации FGS** (`PlaybackService`): полевые репорты — часть прошивок через десятки минут молча снимает у FGS статус переднего плана; процесс в кэш → заморозка → звук. Пока играет, служба раз в минуту заново утверждает `startForeground` (`assertForeground`, `ServiceCompat` с типом mediaPlayback; это не «старт из фона» — служба уже жива), плюс немедленно при возврате к игре в `refreshMeta`. Fail-open.
  6. **Подмена видимости продублирована на уровне диспетчера**: `PlaybackWebView.dispatchWindowVisibilityChanged` — на части прошивок сигнал доходит только по цепочке dispatch от корня, минуя onWindowVisibilityChanged.
  Проверки: check_piko_1323.py (25 файлов, правила, версия), test_unmask_port.py (303/0), scan_redundant_init.py (17 известных ложных срабатываний, нового нет). Вне кода (сообщить владельцу): если прошивка агрессивная (MIUI/HyperOS и т.п.) — включить «Автозапуск»/«Без ограничений» для PikoVK и нажать кнопку исключения из оптимизации батареи в настройках (раздел «Медиа», 1.3.14).
- **НАТИВНЫЙ ПЛЕЕР В СЛУЖБЕ** (жалоба повторилась ВТОРОЙ раз после обоих фиксов: «проигрыватель по прежнему отключает аудио при сворачивании и в фоне и по прежнему скидывает»). Вывод: звук, живущий в WebView (рендерер — отдельный дочерний процесс), на устройстве владельца убивается СИСТЕМОЙ независимо от всех страховок (FGS/wake-lock/приоритет рендерера/подмена видимости/обработчик смерти рендерера) — борьба за жизнь рендерера проиграна. Решение — как у всех настоящих плееров: ЗВУК ПЕРЕЕХАЛ В СЛУЖБУ, нативный MediaPlayer внутри PlaybackService; WebView больше не участвует в воспроизведении вообще.
  - **PlaybackService** стал полноценным медиа-плеером: `startNative` (setAudioAttributes/prepareAsync/onPrepared-start, seek из payload), pause/resume/seek, onCompletion/onError → страница ведёт очередь; **аудиофокус** (AudioFocusRequest, GAIN/LOSS/TRANSIENT, авто-возврат после навигатора), **пауза при вынимании наушников** (ACTION_AUDIO_BECOMING_NOISY), **позиция** (тикер 1 с: readPosition → кэш lastPos → MediaSession-ползунок шторки + пуш `__vkbMusicPos` в страницу), PlaybackState с SEEK_TO (ползунок на локскрине), nPlay/nPause/nResume/nSeek/nativeState из companion (pendingPlay-буфер, если службы ещё нет), updateMeta теперь постится на main (MediaPlayer не потокобезопасен).
  - **music.html** — пульт: `<audio>` и hls.js удалены из воспроизведения (loadIntoAudio → `VkbMusic.nativePlay({url,title,artist,duration,rawId,seek})`), прогресс — из службы (`__vkbMusicPos`), конец/ошибка трека — `__vkbMusicEnded` (повтор/следующий — здесь, очередь не уехала из страницы), seek через `nativeSeek`, `togglePlay` умеет продолжать трек из службы прошлой сессии, при старте вкладка делает `syncPlayer()` — карточка оживает с текущим треком/позицией. `assets/hls.min.js` оставлен как запас (не подключён).
  - **Поведения как у настоящих плееров**: закрытие вкладки и уничтожение ЛЮБОЙ активити музыку НЕ останавливают (MusicActivity.onDestroy глушит службу только при пустом движке; MainActivity.onStart/onDestroy учитывают nativeActive); карточка всегда открывает вкладку, пока в службе есть трек (`fromMusicTab || nativeActive`), свежая вкладка синхронизируется.
  - Разрешения/манифест НЕ менялись — всё нужное было (FOREGROUND_SERVICE, FOREGROUND_SERVICE_MEDIA_PLAYBACK, WAKE_LOCK, POST_NOTIFICATIONS, тип mediaPlayback); FOREGROUND_SERVICE_DATA_SYNC не нужен (это для dataSync-служб). Ревью диффа (свежий взгляд): 0 ошибок компиляции; исправлены 3 логические находки (pageJs при синхронной ошибке setDataSource; очистка pendingPlay в onDestroy и при отказе start; MediaPlayer только с main — кэш lastPos). Проверки: JS node --check OK, 303/0, стиль OK.
- **ОЧЕРЕДЬ ПЕРЕЕХАЛА В СЛУЖБУ** (жалоба после нативного плеера: «аудио работает, но треки вперёд не переключаются как при нажатии кнопки, так и после завершения»). Воспроизведено на стенде (headless-браузер + мок моста): после пересоздания вкладки (закрыл → открыл с карточки, смерть рендерера, убийство активити системой) страница СВЕЖАЯ, `syncPlayer` подтягивает из службы текущий трек, но очередь страницы ПУСТА (жила в JS и умирала вместе с WebView — это даже было задокументировано комментарием в MusicActivity) → кнопка «⏭» и автопереход молча ничего не делают; next/prev шторки без вкладки тоже не работали (pageJs в пустоту). Решение — очередь как у настоящих плееров, в самой службе:
  - **PlaybackService**: очередь хранится в companion (`queueTracks`/`queueOrder` JSON + `orderPos`/`queueIndex`/`queueShuffle`/`queueRepeat`, касание только с main); страница один раз отдаёт список играбельных треков и номер (`nativeQueue {tracks,index,shuffle,repeat}` — старт службы с упреждением, как nPlay); **авто-переход по завершению/ошибке делала сама служба** (`onCompletion/onError → handler.post shiftQueue(1,true)` — release плеера из его же колбэка через post; `errStreak` против вечного цикла битых ссылок), правила: repeat=one → рестарт, repeat=all → по кругу, default → пауза на конце; **next/prev шторки/гарнитуры** — напрямую в очередь (`dispatch`), без вкладки; prev — с откатом в начало трека (>3 с); шаффл — Фишер–Йетс в `rebuildOrder` (текущий первым), порядок живёт в `queueOrder`; пустой url в очереди трактуется как битая ссылка (шаг дальше); смена трека пушит полную карточку в вкладку (`pushState` → kind:'player' + cover + режимы — свежая вкладка оживает целиком); `__vkbMusicPos` получил 5-й аргумент rawId; пустая очередь next/prev — fallback в старый хук страницы (VK-страницы не тронуты).
  - **music.html** — чистый пульт: локальная очередь/шаффл/`__vkbMusicEnded` удалены; тап по треку → `nativeQueue` (фильтр url+restricted, index в отфильтрованном списке); кнопки/шторка → `nativeShift(±1)`; шаффл/повтор → `nativeMode` и СИНХРОНИЗИРУЮТСЯ обратно из службы (режимы переживают вкладку); подсветка строки — по rawId из пушей службы (класс restricted восстанавливается); seek-запаска — по natRawId.
  - **Кнопка «‹ ВК»** в шапке вкладки (слева от логотипа, `VkbMusic.exitTab` → finish()) — возврат к вкладке браузера (жалоба: «нет кнопки для возврата к вкладке вк»; системный Back работал, явная кнопка — как в VK).
- **КНОПКА СКАЧИВАНИЯ В ПЛЕЕРЕ + ДИСПЕТЧЕР ЗАГРУЗОК** (жалоба: «кнопку скачивания трека добавь и в сам проигрыватель, она должна будет скачать тот трек что играет. Так же нужен диспетчер загрузки»):
  - **`music/TrackDownloader.kt`** — единый диспетчер: `enqueue(ctx,url,hls,name)` для mp3 и HLS; задачи в списке (50, подрезка только завершённых), статусы в очереди/качается/готово/ошибка/отменено, прогресс %, отмена флагом (поток останавливается на очередном куске, недокачанное удаляется через `dropPartial`); mp3 качаем СВОИМ HttpURLConnection (cookie сессии + UA WebView — как у всех запросов вкладки) ради живого прогресса и отмены; системный DownloadManager остался на страницах VK (VkbBridge.enqueueNamed). Список задач НЕ в сервисе — переживёт вкладку, умрёт с процессом (для треков приемлемо).
  - **Кнопка «⤓» в самом плеере** (левый нижний угол, рядом с текущим временем): `VkbMusic.downloadCurrent()` — данные берутся из СЛУЖБЫ (`currentDownload()`: ссылка/тип/имя текущего трека хранятся в службе), поэтому работает и после пересоздания вкладки, и для очереди из другого списка.
  - **Вкладка «Загрузки»** в music.html (4-я вкладка): снимок `VkbMusic.getDownloads()` (синхронная строка из JS-моста), опрос 800 мс со снапшот-сравнением (без перерисовки без изменений), статусы с иконками и прогресс-баром, кнопка ✕ у активных (`cancelDownload(id)`).
  - **MusicApi**: `openOutput(ctx,fileName,mime)` — обобщённый вывод в «Загрузки» (MediaStore на 10+, публичный каталог на 8–9, при отказе — каталог приложения), `finishOutput` — публичная финализация IS_PENDING (без неё mp3 НЕ ВИДЕН в «Загрузках» на Android 10+), `dropPartial` — удаление недокачанного, `downloadHls` получил параметр отмены и честный разбор мастер-плейлиста (`firstVariantUrl` — URL ВАРИАЦИИ, а не сегмента — раньше в downloadHls сегмент скармливался как плейлист), `agent()` открыт для TrackDownloader, кэш битрейта → ConcurrentHashMap (пробы из параллельных JS-потоков).
- Проверки доработки: стенд headless-браузера (мок моста): тап по треку → nativeQueue с верным index; все кнопки → nativeShift/nativeMode/downloadCurrent/exitTab; вкладка «Загрузки» — 3 строки со статусами/прогрессом/отменой; пустой раздел; режимы синхронизируются из службы на свежей вкладке (шаффл вкл/повтор all воспроизведены); 0 ошибок JS. Ревью субагентами Kotlin и JS: найдены и исправлены IS_PENDING-слепота mp3, мастер-плейлист HLS, пустой url в очереди (застревание), подрезка живых задач, гонка подсветки restricted; синтаксис node --check OK; check_piko_1323.py OK (26 файлов).

## 1.3.22 (versionCode 27) — фикс: звук при заблокированном экране

- Симптом владельца: «при блокировке экрана аудио не воспроизводится» (при свёрнутом приложении с включённым экраном звук был, при блокировке — нет).
- **Упреждающий запуск FGS, пока приложение видимо.** Официальная рекомендация Android 17 «Background audio hardening» (developer.android.com/about/versions/17/changes/bg-audio): FGS типа `mediaPlayback` надо стартовать, пока приложение на экране, — служба, запущенная уже при погасшем экране (старое поведение: только `onStop`), теряет статус while-in-use, и система молча глушит звук. Теперь `VkbBridge.playerState` (репорт playing приходит сразу после тапа пользователя) запускает `PlaybackService` немедленно; `onStop` остаётся добором. Новое `PlaybackService.isRunning()` — без повторного startForegroundService.
- **Подмена видимости страницы на уровне JS** (секция `VISIBILITY_JS`, тот же тумблер «Фоновое воспроизведение», что и `PLAYER_JS`): дополнение к `PlaybackWebView` (1.3.18 подменял видимость только на уровне View/окна). `document.hidden`/`webkitHidden`/`visibilityState`/`webkitVisibilityState` переопределяются на «видима», `visibilitychange` глушится в фазе захвата на window и document (наши слушатели — document-start, раньше скриптов VK). Плеер страницы не получает сигнала «страница скрыта» ни по одному пути.
- Контроль: `scripts/check_piko_1322.py`. Фикс компиляции из 80ea881 (проверка `intent == null` в `PlaybackService.onStartCommand`) включён в эту версию.

## 1.3.21 (versionCode 26) — музыка: скачивание треков + медиашторка

- **Кнопки скачивания у треков** (по образцу VK Music Saver от VK Next): новая JS-секция `AUDIO_DL_JS` в `ExtensionEngine` — у каждой строки Музыки vk.ru/vk.com кнопка «↓»; клик передаёт «Исполнитель - Название» в `VkbBridge.downloadAudioTrack`, включает трек; `AudioGrabber` (новый, `browser/`) ловит в `shouldInterceptRequest` адрес аудио-CDN (vkuseraudio.net, .vk-cdn.net) и качает файл в «Загрузки» под этим именем. Тумблер «Кнопки скачивания у треков (Музыка VK)», по умолчанию включён. Ограничение честно: если трек уже загружен в плеер (пауза) — ссылки нет, нужен повторный клик.
- **Переработанный плеер в шторке** (по образцу VK Next): `PlaybackService` получил `MediaSessionCompat` + `MediaStyle`-уведомление (новый канал `vkb_playback_ctrl`, IMPORTANCE_LOW) — исполнитель/название и кнопки «назад / пауза / вперёд» в шторке и на локскрине. Команды: `PlaybackService.attach(webView)` → `evaluateJavascript` → `window.__vkbPlayerCmd` (секция `PLAYER_JS`) кликает штатные кнопки плеера VK; метаданные обратно через `VkbBridge.playerState` (репорт раз в 3 с, только при изменении). Гарнитура/Bluetooth: play/pause/next/prev.
- `POST_NOTIFICATIONS` теперь запрашивается и для медиашторки (Android 13+), даже если опрос уведомлений выключен.
- Зависимость `androidx.media:media:1.7.0`. Контроль: `scripts/check_piko_1321.py`.
